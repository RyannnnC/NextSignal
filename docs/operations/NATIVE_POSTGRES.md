# Native PostgreSQL verification

## Prerequisites

Node.js 24, installed dependencies, Docker Desktop with a **healthy Linux engine**, Docker Compose v2 and available loopback port 54329 are required. Use `docker info` to confirm readiness. Installed Desktop/WSL alone does not satisfy this requirement. Do not substitute a PGlite run or mark this check skipped/passed when Docker fails.

```sh
npm ci
docker info
npm run test:postgres
```

The runner generates a unique Compose project and random test credentials, starts `postgres:17`, waits for health, applies existing migrations and executes `vitest.native.config.ts`. Test pools have distinct backend/queue login roles; neither role is superuser or has BYPASSRLS. The database is named nextsignal_native_test. The auth schema is a local test shim, not a Supabase Auth implementation.

Four OS processes synchronise readiness and drain a shared native queue; assertions require more than one worker to process work, exactly one report/call per run, and no tenant leaks. Additional cases exercise concurrent idempotency, SKIP LOCKED under a held row lock, expired-lease fencing, non-superuser RLS and reverse rollback/reapply.

The Compose service exposes only 127.0.0.1:54329 and uses tmpfs. It does not touch .local/db or existing containers. Cleanup targets only the random project generated by this invocation. If startup creates resources but cleanup fails, the runner prints that exact project name for manual inspection. Never run broad Docker prune commands to clean a failed test.

`npm run check:all` combines base checks, native concurrency/RLS, isolated import tests, PostgreSQL-backed browser checks and persistent-container restart checks. GitHub CI has a separate native-postgres job; configuration is not evidence that it has passed remotely.
